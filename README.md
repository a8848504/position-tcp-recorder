# 定位系统 TCP 录制与回放工具

Windows 原生界面，单个 EXE 内置抓包分析组件。运维人员无需安装 Wireshark、Java、Python 或 Go；默认抓包使用 Windows 自带组件，不安装 Npcap 驱动。首次启动需要允许管理员权限，并自动把内置组件准备到用户的本地应用数据目录。

当前版本 **1.4.0**。支持启动自动检查 GitHub 新版本、下载进度、校验和原地更新；TCP 回放支持暂停和继续。

- [下载最新 Windows x64 版本](https://github.com/a8848504/position-tcp-recorder/releases/latest)
- [公开源代码](https://github.com/a8848504/position-tcp-recorder)

## 运维使用

1. 将 `PositionTCP-Windows-amd64-1.4.0.exe` 放到目标 Windows 电脑，双击运行，允许管理员权限。发布文件名带版本号，窗口标题显示相同版本，方便区分现场新旧程序。
2. **录制在运行定位服务的电脑上进行**。定位服务保持运行，硬件继续连接原 IP 和端口。
3. 输入定位系统接收硬件数据的 TCP 端口，可填写“本次备注”，保持“系统免安装（推荐）”，点击“开始抓包”。录制中每秒更新实时接收量、数据段数、当前连接数、时长和抓包文件大小，并提示等待数据、正在接收或最近无新增。
4. 现场数据采集完成后，点击“结束抓包并保存”。等待整理和分析完成，列表状态变成“可回放”。
5. 在测试环境启动定位系统，选择列表中的录制，填写测试目标 IP、端口和倍速，点击“开始回放”。
6. 点击“暂停”冻结全部回放连接的播放时间轴；点击同一按钮“继续播放”后，保留连接并按剩余间隔继续发送，不补发暂停期间的时间。暂停前已交给 TCP 的字节可能仍在传输。暂停时也可点击“停止回放”；完成或停止后关闭本次回放连接。若目标服务有空闲超时，长时间暂停可能使目标服务断开连接，此时显示实际发送错误。
7. 选中一条录制，在“所选备注”中填写情况，点击“保存备注”。备注会显示在列表中，重开工具后保留；旧版本录制也可以补填备注。最多 500 个字。
8. 选中录制后点击“删除录制”，确认框显示时间、端口和备注，默认选择取消。确认后删除该录制及其全部抓包文件。录制、分析、回放或删除过程中禁止再次删除。
9. **选择录制 → 输入上报周期（默认 2 秒）→ 可填写设备 MAC → 点击“分析报告”**。多个 MAC 用逗号、分号或空格分隔，例如 `aabbccdd,11223344`；也支持中文分隔符和 `AA:BB:CC:DD` / `11-22-33-44` 写法，大小写不敏感，重复值会合并。填写报告中的完整“设备 ID”，精确匹配，不按后缀匹配，也不是电脑网卡的 MAC。每次最多 128 个；留空时分析全部。没有有效数据的 MAC 会在报告明确列出。工具在后台生成报告后自动用 Windows 默认浏览器打开本地 HTML；无需安装额外运行环境。
10. Netsh 结束转换失败的旧录制：保留 `capture.etl`，更新工具后选中该条录制，点击“重新整理”，会重新转换、筛选并校验。这个操作不会重新启动或停止系统抓包会话。若原 ETL 确实不含网络包，重试不能补回未捕获的数据；请保留 `conversion.log` 和 `port-diagnostics.log` 排查。

## 自动更新

右上角显示当前版本和“自动更新”按钮。启动时在后台检查正式版；发现更高版本，在旁边以红色显示“发现新版本 vX.Y.Z”。点击按钮会检查版本，确认后下载，进度条显示百分比和已下载大小，可取消下载。无需 GitHub 登录或令牌；需要能访问 GitHub。

文件大小、SHA-256 和 Windows 架构校验通过后，程序退出、替换当前 EXE 并重启。更新保留原 EXE 的文件名，当前运行版本以右上角显示为准。已有录制和备注仍保存在原目录。EXE 需放在有写权限的本地目录。抓包、整理、分析或回放期间禁止安装更新；后台检查只显示提示。下载失败不替换旧文件；重启失败会尝试恢复旧版本。

1.3.0 及更早版本还没有更新入口，需要先手动下载一次 1.4.0；之后可通过右上角更新。在线更新只下载 EXE，完整依赖源码、许可证和便携包随同一 GitHub Release 提供。

## 分析报告

- 按网关、设备 ID、协议分别展示实收条数、理论应收、数量差额、间隔中位数/P95、最长上报空档和原抓包帧号。
- 填写设备 MAC 后，设备表、曲线、逐帧/间隔 CSV 只统计这些设备；TCP、外层封装、未知载荷总数仍为所选端口整体。无法归属设备的载荷不在筛选报告中展开。报告说明筛选范围、扫描/保留/排除条数及没有匹配到有效帧的 MAC。
- 支持设备筛选、上报时间线、间隔折线与对数坐标；理论周期支持 2、2.56 等小数。排查阈值为理论周期的 1.5 倍。
- 展示 TCP 重传、去重、乱序、重组后字节缺口、截断、零窗口，以及协议校验失败和未识别载荷。真实缺口前后分别拆帧，避免拼接出假报文。
- L/C/TA/R 参考定位源码；TO/01/24 和 C/0x28 为样本结构推断并验证长度/帧尾/校验和，报告会说明字段依据。未知协议只提供 TCP 和识别统计，不伪造设备丢包率。
- 数量差额不是确认丢包数，包号缺失也依赖硬件计数规则。录制首尾、不同上报周期、设备停发、无线覆盖、网关转发及业务解析需分别核对。
- 每次报告保存在所选录制目录下独立的 `analysis-日期时间-编号` 文件夹，包含 `report.html`、`report.json`、设备统计/上报间隔/逐帧/异常 CSV；再次分析保留之前的报告。整个文件夹可以复制给同事离线查看。
- 报告生成不会改写原抓包、`events.tcr`、备注或可回放状态。原“重新分析所选录制”按钮改为“重新整理”，继续用于整理/修复回放文件。
- 最多分析 1,000,000 条有效内帧和 4,096 条 TCP 流，乱序缓存最多 128 MiB。图表每组最多约 5,000 个采样点，统计和 CSV 使用全量数据，最长空档保留。遇到上限明确提示分段录制。

录制默认保存在 `%LOCALAPPDATA%\PositionTCP\recordings`。界面的“打开录制目录”可打开所选录制；没有选中项时打开全部录制目录。更新工具不会删除已有录制。每个文件夹包含 `recording.json`、原始 `traffic.pcapng`、`events.tcr` 和诊断日志。

## 实时显示口径

- “上报数据”在录制中显示 Windows 针对所选服务端口的实时接收采样估算，包含重传；不是磁盘文件大小。现有连接以开始时的统计作为基线，不把录制之前的累计流量算入。
- 实时窗口单独显示抓包文件大小/数量，文件头和预分配空间不会被当成硬件业务数据。端口有接收而尚未生成抓包文件时会明确提示。
- 实时显示用于观察数据是否持续到达，不能证明抓包完整性；在首次启用统计之前收到的数据以及采样间隔内建立又关闭的极短连接可能漏计。停止保存后的数据量仍以原始抓包重组、去重结果为准。
- 某连接的系统统计不可读取时提示不可用或不完整，不会把读取失败当成收到 0 字节。统计查询不影响原来的抓包和回放。
- 实时列表刷新不会重载正在编辑的备注。保存当前录制的备注后，结束分析会保留最新备注。

## Windows 支持与免安装

- 目标为 Windows 10/11、Windows Server 2019 及以上的 **x64** 系统。
- 新版系统使用 Pktmon：只采集指定 TCP 端口，在网卡层保存完整报文，按大小滚动新建文件，不覆盖旧记录。
- 较旧的 Server 2019/Windows 10 使用 Netsh 兼容方式。该方式会临时采集本机 TCP 流量，开始前明确提示并征求同意；停止后使用内置 Microsoft etl2pcapng 转换，筛选出所选端口后删除宽范围临时文件。转换失败时保留临时文件以便恢复，不会假装保存成功。
- 如果电脑已经安装 Npcap，也可以选择“Wireshark（已有 Npcap）”，调用内置 dumpcap 采集本机所有 Npcap 网卡。
- **不会安装、静默安装或分发 Npcap**。Npcap OEM 分发授权是独立于 Wireshark GPL 的事项。
- 原生系统模式在网卡层采集，适合真实硬件到服务器的流量；同机 `127.0.0.1` 自测流量应使用已安装 Npcap 的 Wireshark 模式。回放本身支持目标 `127.0.0.1`。
- 本工具不会占用定位服务的接收端口，也不会改动硬件连接、服务配置或防火墙配置。
- 系统已有其他 Pktmon/Netsh 抓包时，不接管或停止其他工具的任务；Pktmon 已有筛选规则时不会擅自清除它们。

## 回放行为与完整性

- 回放建立**真实的新 TCP 连接**，每条录制会话对应一条目标连接；不是把原 TCP 网络包直接注入网卡。
- 只向目标发送录制中“硬件 → 所选服务端口”的业务字节。录制的服务端回复保留在原始抓包中，回放时持续读取新服务的实际回复。
- 按 TCP 原始序列号重组，处理重传、部分重叠和乱序；保留各会话在共同时间线上的相对时间，支持 0.5、1、2、5 倍速。
- 含 TCP 序列缺口、截断报文、损坏回放文件的录制不会静默回放。回放文件每条记录有 CRC 校验，并在连接目标之前完整校验。
- 录制可能从已建立连接的中途开始，此时会在列表标记提示，回放前再次明确提示。为了录下登录等初始交互，可先开始抓包再让硬件重新连接。
- 不保证重现原来的 TCP 分包边界；重现的是应用字节流和尽可能接近的发送时序。操作系统调度、目标响应和网络会影响实际发送时间。
- 本版本面向当前定位系统的原始二进制 TCP 上报。TLS 密文、需要根据新服务动态口令生成登录报文、或严格等待特定应答才能发送下一条请求的协议，需要额外适配；不是通用的有状态协议仿真器。
- 定位系统使用系统时间、数据库和缓存状态，因此重复输入不等于定位结果必然逐字节一致。算法比较宜先用原速回放并固定测试配置和初始状态。
- 最多记录 4096 条会话、最多同时回放 1024 条连接；TCP 乱序缓存限制 128 MiB。遇到上限会明确报错。
- 抓包会持续占用磁盘；请根据实际数据量留足空间。原始抓包与转换过程可能同时存在，建议空闲空间至少为预计原始抓包体积的 3 倍。正常结束可完成保存；进程被强制结束或主机断电可能留下未完成记录，原始文件仍保留。

## 开发与重新打包

本仓库是独立 Go 程序，不依赖定位服务的 Maven 项目。

构建机需要 Go 1.26 及以上、Python 3.9 及以上、7-Zip。最终运维电脑不需要它们。

```sh
go test -race ./...
go vet ./...
python3 scripts/package.py --go /path/to/go --sevenzip /path/to/7zz
```

打包脚本固定第三方版本和 SHA256，递归解析 Windows PE 导入以打包 tshark、dumpcap、mergecap 所需 DLL，内嵌到单 EXE。构建时生成管理员权限清单及 Windows Common Controls 资源。可从 macOS/Linux 交叉构建 Windows x64。

便携包附带本工具源码、Wireshark 同版本源码包、第三方许可证和 SHA256 清单。整个包请一并保留，用于依赖溯源和再次分发。

离线分析诊断入口：

```sh
go run ./cmd/tcp-recorder --analyze /path/to/tshark /path/to/capture.pcapng 9000
go run ./cmd/tcp-recorder --report /path/to/tshark /path/to/capture.pcapng 9000 2 /path/to/report-output
go run ./cmd/tcp-recorder --report /path/to/tshark /path/to/capture.pcapng 9000 2 /path/to/report-output 'aabbccdd,11223344'
```

`--analyze` 为原有回放文件整理入口；`--report` 为 HTML 分析入口，可省略周期和输出目录（默认 2 秒、写入抓包目录下的独立报告目录）。应用内按钮和 CLI 使用相同分析代码。

## 验证边界

本地可自动验证 TCP 字节重组、二进制完整性、多连接、时间间隔、损坏文件、取消和连接失败，并交叉编译 Windows EXE。**macOS 构建不代表 Windows 驱动、管理员提权、原生界面、Pktmon/Netsh 已实机验证**；发布前应按 `WINDOWS-VALIDATION.md` 在目标 Windows 机器完成验收。

## 发布新版本
